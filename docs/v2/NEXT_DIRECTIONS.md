# Next Directions — What to Build & Learn

Three candidate directions for the next phase of the project, ordered by
learning density. Each combines a **buildable deliverable** with **new concepts**
that deepen understanding of agentic AI engineering.

---

## Direction 1: Onboarding Interviewer Agent

**Build:** An agent that turns a real person into a `pair_XX.json` profile through
a multi-turn adaptive conversation (not a form — probes deeper on ambiguous answers).

**Learn:**
- Prompt chaining with state (the interviewer remembers, decides what to probe next,
  knows when to stop — a different loop engineering problem)
- Schema-as-contract (output must conform to the exact profile schema the council expects)
- Elicitation vs. leading (surface real dealbreakers without planting them)
- Eval for an interviewer (how to measure completeness, consistency, whether it
  surfaced the binding constraint — a genuinely hard eval problem)

**Connects to:** note 01 (loop engineering), note 02 (eval for generative processes),
note 04 (self-correction when the person contradicts themselves)

**Effort:** ~days | **Priority:** next product feature (ROADMAP)

---

## Direction 2: Adversarial Pair Generator ← DOING FIRST

**Build:** A script that generates new labeled pairs designed to *break* the current
system — pairs where the binding constraint is subtle, where the obvious answer is
wrong, where the profiles target known weaknesses.

**Learn:**
- Adversarial/red-team eval design
- Synthetic data generation with quality control
- Curriculum difficulty ordering (easy → hard → where does the system break?)
- The "who labels the labels" bootstrapping problem
- How more data makes the self-improvement loop more powerful

**Connects to:** note 02 (eval resolution — more pairs = taller measuring stick),
note 05 (self-learning — more data to learn from), note 07 (the loop improves with
more labeled data)

**Effort:** ~hours | **Priority:** highest learning-per-hour; immediately strengthens eval

---

## Direction 3: Human-in-the-Loop Review UI

**Build:** A minimal web UI where a human matchmaker reads the debate transcript,
sees the verdict, and can override it. The override becomes a new label.

**Learn:**
- The full feedback loop (human override → new label → re-eval → diagnose → optimize)
- UX for AI transparency (presenting multi-agent debate to non-technical humans)
- Disagreement as signal (overrides are the most valuable data points)
- The option-(c) architecture (system decides vs. system presents tensions for human)

**Connects to:** note 05 (self-learning from human overrides), note 06 (multi-agent
debate is more reviewable than single-prompt — structural advantage pays off here)

**Effort:** ~week | **Priority:** enables real-world deployment and the ultimate
feedback loop (real outcomes)

---

## Sequencing rationale

**2 → 1 → 3** because:
1. Direction 2 is fast and immediately strengthens the eval (the foundation everything
   else depends on)
2. Direction 1 is the next product feature and benefits from having a richer eval set
   (generated by Direction 2) to test against
3. Direction 3 is the deployment story and benefits from both a robust eval AND a
   working interviewer to feed it real profiles

Each direction produces artifacts that make the next one better.
